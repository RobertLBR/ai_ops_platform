**诊断实测数据**：

## 五点五、二期首批功能（2026-09-23 交付）

### 架构审查 10 项修复（commit 47494d9）

SSH 白名单路径穿越加固、非回环监听零认证 fail-fast（删 `?token=` 通道）、巡检免费前置闸（无异常跳过 LLM）、
LLM JSON 修复重试自适应（样本砍半 + maxTokens ×1.5）+ 缓存键 SHA-256、数据生命周期（`storage.retentionDays` 默认 90 天 +
僵尸任务回收）、ES level 大小写兼容、落库脱敏 + 建议命令白名单标注、Prompt 不可信数据边界、Docker 日志轮转/资源限制、
`maxInputTokens` 出口截断。

### 功能一：Web「实时监控」开关

- 平台级开关（App Header），localStorage 记忆，**默认 OFF**（OFF 时零请求零定时器）。
- 前端智能轮询（5s）+ BroadcastChannel 领导者选举（N 个 tab 只有 1 个发请求，leader 关闭 15s 内接管）+
  失败指数退避 5→10→20→40→60s。
- 后端聚合端点 `GET /api/monitor/snapshot`：告警 20 条 + 进行中/最近诊断 + 数据源健康（60s 惰性 TTL 缓存）。
- 监控链路只读 SQLite + 内存缓存，代码上不经过 LLM。

### 功能二：AI 服务配置生成

- 服务注册表页「AI 生成配置」：粘贴日志样例（≤50 行/8KB，先脱敏再出网）→ light 档 LLM 生成草稿 →
  可编辑表单（防抖 500ms 免费校验）→ 备份写回 config.yaml（CST 往返保注释与 `${ENV}` 占位符）→ 热生效。
- 三层校验：未知键白名单（13 个顶层键递归比对）→ `ServiceSchema` → B1-B8 业务规则
  （别名必含中文、fieldMapping 第 1 候选必须在样例字段集中、禁止疑似密钥、instance 禁反斜杠等）。
- 审计：`ai_config_generations` 新表存完整谱系（样例/原始输出/用户 diff/最终配置），
  `audit_log` 写 `ai_config.saved` 指针，文件级回滚用 `config.yaml.bak.*`（留 10 份）。
- 成本边界：analyze 限流 10 次/分钟、maxTokens 2000、样例 8KB 上限、仅点击触发。

## 六、已知问题与待办（二期候选）

| 优先级 | 事项 | 说明 |
|---|---|---|
| 🔴 高 | **LLM JSON 重试不具适应性** | 当前重试用完全相同的参数重发，遇推理模型截断必然连失败两次。建议：失败后降低输入规模 / 追加"只输出 JSON"约束 / 尝试修复截断 JSON |
| 🟠 中 | **`bank_card` 脱敏规则误伤** | `\d{16,19}` 会把日志里的长数字 ID 一并吃掉（单次可命中 2000+ 次）。过度脱敏不危险，但损失定位信息，应按业务号段收紧 |
| 🟠 中 | **定时巡检默认关闭** | 开启后每轮会对所有非 edge 服务各跑一次诊断（如 9 服务 × 24h ≈ 216 次/天），需先确定 token 预算与扫描间隔 |
| 🟡 低 | **SSH 数据源未接入实际用途** | 只读命令白名单已实现并有自检接口，但尚未在诊断链路中实际调用 |
| 🟡 低 | **案例库自动检索缺失** | 案例沉淀接口已有，但尚未做向量检索召回相似历史案例 |
